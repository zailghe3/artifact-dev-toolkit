# Model capability and hardcoded constraint audit

The inventory covers the Worker, ADT Runtime and persistent execution paths reviewed for the model capability change. A is security or authority, B is protocol, infrastructure or durability, C is an operational safeguard or default, D is product design, and E is a potentially unjustified capability limitation.

## Provider evidence and remaining work

- OpenAI’s Models API identifies available models without a function-calling or parameter matrix. The Chat Completions reference defines request fields. The exact Luna and GPT-5 pro model pages establish the preflight exceptions. GPT-6 Luna with reasoning enabled requires a journaled Responses implementation to propose tools. The current journal preserves Chat Completions text, function calls and correlated results. A Responses implementation must durably preserve reasoning items required by the model, including encrypted content where applicable, and distinguish external function results from provider-hosted actions. [Models API](https://developers.openai.com/api/reference/resources/models) · [Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) · [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) · [GPT-5 pro](https://developers.openai.com/api/docs/models/gpt-5-pro) · [OpenAI reasoning guide](https://developers.openai.com/api/docs/guides/reasoning)
- Anthropic model lookup supports alias resolution. The metadata reference documents limits and certain features, but does not establish native client tool use for the Messages request as configured by ADT. The adapter uses definitive request rejections for that capability. [Anthropic Models API](https://platform.claude.com/docs/en/api/models/retrieve)
- Ollama’s model details endpoint provides tool capability when the server advertises it. The advertised capability does not guarantee that inference will succeed with the selected model, endpoint and schema. [Ollama model details](https://docs.ollama.com/api-reference/show-model-details)
- Local protocol fixtures exercise OpenAI Chat Completions with GPT-4.1, GPT-6 Luna with reasoning effort `none`, and unfamiliar IDs; Anthropic Messages with Claude Sonnet 4.5 and an unfamiliar ID; Ollama Chat with `qwen3` and an unfamiliar ID. Direct OpenAI Responses fixtures cover explicit options and safe rejection. Worker/Runtime integration exercises authorization, execution, tool-result correlation, and no replay after rejection or ambiguous transport.
- Live provider inference, project availability, undocumented provider error shapes and hosted endpoint compatibility remain unverified. Release the Worker and Runtime through the normal coordinated rollout. The Runtime release revision changes. Current snapshots, journal tables and authentication contracts require no migration.
