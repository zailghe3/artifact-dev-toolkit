# ADT security hardening

Reviewed on 28 November 2026 against `dbc49c0` on `main`. The earlier review used `267ee67`. Deployment conclusions use the documented single-user, split Runner and private-service model. Registry images were inspected by digest. The operator's running container digests and Cloudflare dashboard settings were outside this review.

## Remediation

| Finding | Result |
| --- | --- |
| Executable Markdown metadata | Confirmed. `gray-matter` 4.0.3 ships a JavaScript engine. Artifact reads, Advisor knowledge and repository validation used its normal parser for repository-supplied documents. The Worker, Runtime and CLI now use bounded, data-only YAML and existing metadata schemas. Both manifests and lockfiles remove `gray-matter`. [Upstream language support](https://github.com/jonschlinkert/gray-matter/tree/4.0.3#optionslanguage) |
| MCP endpoint credentials | Confirmed. Definitions accepted HTTPS URLs containing user information, queries and fragments. All three forms now fail validation before Git writes, Runtime calls or run admission. Historical run history remains readable with ineligible endpoint values omitted, and execution fails closed. Existing invalid definitions require repair in Git and policy reauthorisation. |
| Browser mutation protection | Confirmed inconsistent coverage. The shared repository access gate requires an exact same origin for browser mutations and JSON media type for API request bodies. Sign-out preserves form submissions. OAuth callbacks and the repository credential broker retain their purpose-specific checks. Invalid browser requests stop before session resolution, body parsing or privileged work. |
| Auth redirects and resource use | Confirmed. Redirect destinations are checked after URL normalisation and across encoded path forms. The Worker rejects malformed session IDs before D1, bounds OAuth inputs, applies GitHub request deadlines, reuses private-key readiness checks and skips persistent session creation on allowlist denial. Valid-looking unknown session IDs still require D1. |
| Public Worker exposure | Preview URLs are disabled. Responses carry MIME sniffing, clickjacking and referrer controls, and authentication and sensitive responses use private, no-store caching. Deployment details moved to authorised pages and server-side bindings. A script CSP is deferred because Next.js hydration and the existing theme loader use inline scripts. |
| Log exposure | Confirmed locally in Adrian's former unstructured payload handling and Runner's request-path diagnostics. Adrian now filters recognised credential fields and text before sending observations. Runner records allowlisted operations. Runtime hashes signed request nonces in readiness and invalid-request logs. Worker invocation logging is disabled and query redaction is enabled while custom operational events remain available. [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/) [Wrangler settings](https://developers.cloudflare.com/workers/wrangler/configuration/) |

## Credential review

- Gitleaks 8.30.1 scanned the current tracked trees and available history for both repositories with full redaction. ADT flags were synthetic GitHub token and malformed key fixtures. The private repository flags were vault reference identifiers. No credential value was printed or confirmed exposed. The private repository had no tracked MCP definitions in the available history.
- Reviewed Worker, Runtime, provider diagnostics, Runner, Adrian, Workflow snapshots and conversation persistence. Provider and service credentials are vault-backed or transmitted in scoped headers and envelopes. Workflow and conversation text can contain secrets pasted by the user or echoed by a tool. Restrict access and retention for that content and for Adrian telemetry. Pattern-based redaction covers recognised credentials and leaves ordinary security evidence intact.
- Inspect retained Cloudflare invocation logs and any existing Logpush, traces or tail consumers for previous OAuth query strings and authentication headers. Use a staging synthetic code and cookie to verify downstream collectors after rollout. If a credential was captured, identify the principal and scope, revoke or rotate it through the owning provider, and investigate access within the exposure window. Apply the existing retention or incident process to affected records.

### Edge rate limits

Scope each rule to `http.host eq "adt.pouchet.net"`. Start with per-IP counting and a block response of HTTP 429 for 60 seconds, using the closest plan-supported period. Tune using legitimate login and service volumes.

| Match | Starting threshold |
| --- | ---: |
| `GET /sign-in` | 60 requests per minute |
| `GET /auth/github/start` | 15 requests per minute |
| `GET /auth/github/callback` | 30 requests per minute |
| `POST /api/runtime-repository-credential` missing the expected `x-adt-protocol` header | 30 requests per minute |

Use exact paths. OAuth callbacks are browser navigations from GitHub, so avoid source-IP allowlists and interactive challenges on that path. Keep supported signed broker traffic outside the low anonymous limit. If a broker-wide limit is needed, set it above observed Runtime bursts and use a noninteractive action. [Cloudflare rate limiting rules](https://developers.cloudflare.com/waf/rate-limiting-rules/)

### Optional Cloudflare Access

Protect `adt.pouchet.net` with a self-hosted Access application that permits one verified identity at an MFA-capable identity provider. Retain ADT's GitHub OAuth, login allowlist, repository checks and sessions. Cover the GitHub start and callback paths with the same browser policy. Use an Access session longer than the OAuth exchange and validate the top-level redirect and cookies on desktop and mobile. Restart the sign-in flow if Access expires during a callback.

Give `/api/runtime-repository-credential` a more specific Access application with a Service Auth policy for one dedicated Runtime service token. Add its header support to Runtime and provision the client ID and secret through managed Runtime secrets. Keep the existing signed payload, replay checks and scoped GitHub authority. Use a separate, narrowly scoped CI Access token if the production OAuth smoke requires one. Avoid a public bypass for either path.

First close alternative hostnames after the broker cutover. Validate anonymous denial, permitted browser login, an unapproved identity, signed broker calls with and without the Access token, and deployment smoke in a test environment. Roll back by removing the Access enforcement and restoring the previous Runtime token configuration while retaining ADT authentication. Record token expiry, rotation ownership, mobile/browser validation and break-glass access before enabling the policy.
